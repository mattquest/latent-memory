# Auxiliary reranker provenance

The optional reranked-RAG arm uses the official [Qwen3-Reranker-0.6B checkpoint](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B/tree/e61197ed45024b0ed8a2d74b80b4d909f1255473), pinned to revision `e61197ed45024b0ed8a2d74b80b4d909f1255473`. The [model card at that revision](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B/blob/e61197ed45024b0ed8a2d74b80b4d909f1255473/README.md) declares Apache 2.0. Attribution: Qwen Team; Zhang et al. (2025), *Qwen3 Embedding: Advancing Text Embedding and Reranking Through Foundation Models*.

[`reranker-model-manifest.json`](reranker-model-manifest.json) records the exact source revision and SHA-256/size receipts for the downloaded files, including the weights and tokenizer. All 1,207,485,750 downloaded bytes were checked against those receipts on CPU. The tracked manifest contains no model weights. The weight-file SHA-256 is `27cd75a405b9c1b46b59abfd88aaa209e6fed2a1972cde9b70e7659537c5e65b`; the model-card hash is `5bba8c734f6dd3ae48317b4139317e45a7fce48fc55e15670b23a0dd15492ab6`.

The local helper follows the model card's Transformers scoring recipe. It constructs the same system/user/assistant framing and default retrieval instruction, takes the final-position logits for `no` and `yes`, and computes the two-label softmax probability of `yes`. The host implementation uses the algebraically equivalent sigmoid of the logit difference. Scores rank document relevance; they are not calibrated probabilities that the final generated answer is correct. The tokenizer maps `yes` to token 9693 and `no` to token 2152.

A CPU-only tokenizer audit compared the helper against the published Transformers input recipe for short, Unicode, and truncated passages at both 2,048 and 8,192 tokens. All six input-token sequences matched exactly. The helper preserves the complete question and rejects a query that leaves no document room; the official single-string truncation example could truncate such an oversized query. This deliberate guard does not alter normal in-budget prompts.

The local run has explicit differences from the published evaluation: a 2,048-token scoring cap, BF16 MLX execution, one document per forward call, no shared-query prefix cache, BM25 top-20 candidates, and six selected paragraphs supplied to the same Qwen3-8B answering model. The model-card Transformers example uses an 8,192-token cap, while its published retrieval tables rerank top-100 candidates from Qwen3-Embedding-0.6B on other evaluation suites. Our MuSiQue answer accuracy and latency therefore do not reproduce or substitute for those published reranking scores. This audit did not establish numerical parity between MLX and Transformers; runtime preflight results must be reported separately. The CPU audit establishes token framing and scoring-formula fidelity only.

Model loading and checksum verification are setup costs. Each query must include candidate tokenization, scoring forwards, synchronization, selection, and answer generation in its measured cost. The reranker generates zero output text tokens, but its forward computation is not free. Both models share the same process memory limit; the auxiliary model receives no additional memory allowance.
